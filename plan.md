## 1. Executive Summary

### 1.1 What we are building

A **documentary website** for the Sylhet Division delivery of the Government of Bangladesh
programme *"তথ্যপ্রযুক্তি জ্ঞানসম্পন্ন যুবদের কৃত্রিম বুদ্ধিমত্তা (এআই) প্রযুক্তির মাধ্যমে দক্ষতা
উন্নয়ন"* — implemented by **যুব উন্নয়ন অধিদপ্তর (Department of Youth Development)**, Ministry of
Youth & Sports.

The site tells the story of **Batch 1 in Sylhet**: who took part, where they came from, what they
learned and what they have done since. It also documents the course itself — curriculum, duration,
the training institution, and the facilities.

It is **not** an operational system. There is no application form, no exam engine, no student
portal and no certificate verification. See §2.

### 1.2 Shape of the product

| Piece | Description |
|---|---|
| **Public site** | Section-built pages: Home, The Course, Batch 1, Participant profile, Districts, Gallery, Notices, About, Contact, Privacy |
| **Admin CMS** | A **single admin user** enters and manages all content: pages, participants, course, media, notices, settings |
| **Data** | Batch 1 participant records (names and details), aggregate statistics, course/curriculum, media library |

### 1.3 Stack

Chosen to match the owner's already-live deployment (`favoniahobbies.com`), so `deploy.sh`, cPanel,
Passenger and CI are proven rather than new.

| Layer | Choice |
|---|---|
| Language / framework | **Python 3.12 · Flask 3.1** (blueprints) |
| ORM / DB | Flask-SQLAlchemy · **MySQL** (`utf8mb4`) in prod, SQLite in dev |
| Auth | Flask-Login + Flask-Bcrypt — **one admin role** |
| Forms / CSRF | Flask-WTF / WTForms |
| Images | Pillow (resize, re-encode, EXIF strip) |
| CSS | **Tailwind CSS v4** — compiled `app/static/css/app.css` is committed; server needs no Node |
| Host | cPanel + Phusion Passenger |
| CI/CD | GitHub Actions — push to `main` deploys, gated by a blocking validation job |

### 1.4 Effort

**~40 developer-days solo ≈ 8 weeks**, on one developer. Session One (a browsable, publishable site
with Batch 1 content) lands at **~4 weeks** — see §20.

## 2. Scope & Non-Goals

### 2.1 In scope

- Section-built public pages, CMS-managed
- **Batch 1 participant records** — name, district, upazila, education, and what they did
- Aggregate cohort statistics and district coverage
- Course and curriculum documentation for the Sylhet institution
- Media library (photographs, video links)
- Notices / updates
- Bangla-first typography, responsive to 360px, WCAG 2.1 AA on public surfaces
- A single-admin CMS with a consent-aware participant workflow

### 2.2 Explicitly out of scope

Not deferred by accident — **these are not being built**:

| Not built | Why it is noted |
|---|---|
| Online application form | Applications were handled outside this site |
| Admit card, results, certificate lookups | Operational functions, not documentary ones |
| Exam engine — centres, allotment, roll numbers, marks, merit lists | No exam workflow lives here |
| Student accounts, roll+mobile login, email login, OTP, password reset | There is **one** user: the admin |
| Student portal (~14 screens) | Nothing for a student to log into |
| Enrolment, attendance, class schedules, materials, TA reports | Not part of a documentary site |
| Certificate generation, issuance, revocation, QR verification | Out of scope |
| SMS / email notifications, queue, bulk blasts | No outbound messaging |
| Multi-role RBAC, district coordinators, four-eyes approval | One role, one user |
| Fee or allowance payments | No financial data on this site |
| Import of applications or marks | Only participant records are imported (§11.4) |

> A short "deferred design" note in §23.3 records what the earlier plan covered, so it is not
> re-proposed later without a deliberate decision.

### 2.3 Privacy boundary

The site publishes **people's names and some personal detail**. That is a consent obligation, not a
styling choice. §5 defines the field set, the consent model and the hard prohibitions. The short
version:

- Published: **name, district, upazila, education, what they did**
- **Never published:** photograph, phone, email, NID or birth-registration number, date of birth,
  blood group, full address, guardian names
- A participant without recorded consent is **not published at all**

## 4. Content Model

Everything on the site is one of the content types below. This is the contract between the admin
UI, the database and the templates.

### 4.1 Content types

| Type | Purpose | Count guide |
|---|---|---|
| **Page** | A public page, composed of ordered **sections** | ~10 |
| **Section** | One block within a page, of a fixed type (§4.2) | 3–8 per page |
| **Participant** | One Batch 1 cohort member (§5) | ~100–400 |
| **Course** | The programme as delivered in Sylhet | 1 |
| **Course module** | One curriculum unit within the course | 6–12 |
| **Institution** | The training centre / partner providing the course | 1–3 |
| **Media item** | An image or video in the shared library | 50–300 |
| **Notice** | A dated announcement | unbounded |
| **Stat** | A labelled figure used by stat strips and the cohort summary | ~12 |
| **FAQ** | A question and answer | ~12 |
| **Setting** | Site-wide key/value configuration | ~40 |

### 4.2 Section library

Sections are **a fixed set of types with typed fields** — not a free-form drag-and-drop block
builder.

> **Why fixed and not free-form:** a generic block builder is roughly 4 extra days of work, lets
> the admin produce layout that breaks the design system (§7), and cannot be validated. A fixed
> library is faster to build, impossible to misuse, and still covers every page we need. Adding a
> type later is a small, deliberate change.

| Section type | Fields | Used on |
|---|---|---|
| `hero` | heading_bn, subheading_bn, background_media_id, primary_cta (label+href), secondary_cta | Home, Batch 1, Course |
| `rich_text` | heading_bn, body_bn (sanitised HTML) | About, Privacy, any |
| `stat_strip` | heading_bn, stat_keys[] | Home, Batch 1 |
| `fact_list` | heading_bn, items[] (label_bn, value_bn) | Course, About |
| `module_list` | heading_bn, course_id | Course |
| `participant_grid` | heading_bn, district_id?, limit, sort | Home, Batch 1 |
| `district_grid` | heading_bn, show_upazila_counts | Home, Districts |
| `gallery_strip` | heading_bn, media_ids[], columns | Home, Gallery |
| `media_feature` | heading_bn, body_bn, media_id, layout (left/right/full) | Course, About |
| `notice_list` | heading_bn, limit | Home, Notices |
| `faq_list` | heading_bn, faq_ids[] or category | Course, About |
| `quote` | quote_bn, attribution_bn | Home, Batch 1 |
| `cta_band` | heading_bn, body_bn, cta_label, cta_href | Home, Batch 1 |
| `institution_card` | heading_bn, institution_id | Course, About |
| `timeline` | heading_bn, items[] (date_bn, title_bn, body_bn) | Course, About |

Each section row stores `type`, `sort_order`, `is_visible` and a `content` JSON payload validated
against a schema per type. §9.3 defines the validation.

| Page | Slug | Sections |
|---|---|---|
| Home | `/` | hero · stat_strip · rich_text · participant_grid · module_list · district_grid · notice_list · cta_band |

## 5. Participants & Privacy

The cohort is the centrepiece of the site and the highest-risk content in it. This section is the
authority on what may be published.

### 5.1 Publishable fields

| Field | Published | Notes |
|---|---|---|
| `name_bn` | ✅ | As it should appear publicly. Bangla script. |
| `name_en` | ✅ optional | Only if the participant provided it. Never auto-transliterated — a wrong English name on a government page is worse than no English name. |
| `district` | ✅ | One of the 4 Sylhet districts |
| `upazila` | ✅ | One of 41 |
| `education` | ✅ | HSC / Diploma / Degree / Honours / Other |
| `occupation_before` | ✅ optional | e.g. শিক্ষার্থী, কৃষি — useful context for "what they did" |
| `outcome_type` | ✅ | `employment` · `freelancing` · `further_study` · `business` · `teaching` · `other` |
| `outcome_text` | ✅ optional | One or two Bangla sentences, in the participant's terms |
| `quote_bn` | ✅ optional | Only with explicit consent — see 5.3 |
| `batch` | ✅ | Batch 1 |
| `slug` | ✅ | Derived from `name_en` or a sequence; Latin, stable |

### 5.2 Prohibited fields

**Never stored on this site, and never published:**

photograph · phone · email · NID or birth-registration number · date of birth · blood group ·
full address · guardian or parent names · signature · exam marks · any government identifier.

> **No photographs at all** — decided 2026-09-23. Images of identifiable private individuals on a
> public government page carry a consent burden out of proportion to their value here. The design
> compensates with typography, district data and outcomes (§7.5), not faces.
>
> This also removes the single hardest thing to obtain retroactively. A name can be consented to in
> a message; a photograph, once published, cannot be recalled.

Consequence: **there is no `media_id` on a participant.** If a future phase wants portraits, that is
a new consent programme, not a field addition.

### 5.3 Consent model

| Field | Type | Rule |
|---|---|---|
| `consent_publication` | BOOL | **Required `true`** for the record to be publishable |
| `consent_date` | DATE | When consent was given |
| `consent_source` | ENUM | `written_form` · `sms` · `email` · `verbal_witnessed` · `programme_terms` |
| `consent_notes` | TEXT | Free text — who recorded it, any scope limits |
| `consent_withdrawn_at` | DATETIME | Set when withdrawn; unpublishes immediately |

**Rules**

1. `is_published` **cannot** be `true` unless `consent_publication = true` and `consent_date` is set.
   Enforced in the model, the form **and** a database-level check on write.
2. Withdrawing consent sets `consent_withdrawn_at` and clears `is_published` in the same
   transaction. The next page render excludes them — no cache may outlive this (see §15.1).
3. Records without consent are stored in the admin, badged **"প্রকাশ করা হয়নি"**, and excluded from
   every public query, count, statistic and search index. They are not silently deleted, so the
   cohort total in the admin stays honest.
4. Withdrawal does **not** delete the row — the department needs the audit trail — but the public
   site behaves as if it never existed.
5. `quote_bn` requires its own tick in the CMS, because publishing someone's words is a stronger act
   than publishing their name.

**Consent dashboard** (admin, `/admin/participants/consent`): consented count, not-consented count,
withdrawn count, and a filtered list of anyone missing a `consent_date` — the records most likely to
cause a problem.

### 5.4 Cohort statistics

The site publishes aggregate figures derived **only from consented records**:

মোট প্রশিক্ষণার্থী · জেলা অনুযায়ী সংখ্যা · উপজেলা কভারেজ (x/41) · শিক্ষাগত যোগ্যতার বিভাজন ·
লিঙ্গ (only if recorded) · ফলাফলের বিভাজন (কর্মসংস্থান / ফ্রিল্যান্সিং / আরও পড়াশোনা …)

Rules:
- Every figure recomputes from consented records on read, cached 300 s (§15.1).
- **Gender is optional and off by default.** It is not needed for a documentary page and adds a
  sensitive dimension to every record.
- Never publish a figure that could identify an individual — any cell derived from **fewer than 5
  records** renders as `—`. This matters most at upazila level.

### 5.5 Participant profile page

`/batch-1/<slug>` — one page per consented participant:

```
নাম (name_bn)                        ← largest element
জেলা · উপজেলা                         ← label-value pairs
শিক্ষাগত যোগ্যতা
এর আগে (occupation_before, if present)
[quote_bn, if consented — set as a pull quote]
কী করেছেন (outcome_text)
━━━  ← "the document rule" motif (§7.5)
ব্যাচ ১ · সিলেট বিভাগ
[← সব প্রশিক্ষণার্থী]   [পরবর্তী →]
```

No photograph, no image placeholder, no silhouette graphic. The page is typographic.

## 7. Design System

**Decided 2026-09-23: Direction A + C hybrid — 「সুরমা প্রোটোকল」 (Surma Protocol), built with
Tailwind CSS v4.**

### 7.1 The three directions

| | Direction | Palette | Type | Motif | Verdict |
|---|---|---|---|---|---|
| **A** | Sylhet Green / Tea Estate | tea-garden green `#06301F` → `#14805A`, lime `#8FBF4D`, cream `#F7F5EF`, ink `#111C17` | Noto Serif Bengali display + Noto Sans Bengali + IBM Plex numerals | Surma-valley contour lines, 1px hairline rules | Pleasant, but unserious on its own |
| **B** | Digital Sylhet / Signal | near-black `#0A0F14`, cyan `#00E5C7`, amber `#FFB020`, dark-first | Space Grotesk / Outfit + monospace stats | dot-matrix grid, animated counters | ❌ **Rejected** — fails the trust test for a government programme. Reads as a startup landing page, and ages fast |
| **C** | Official Protocol / Document-led | flag green `#006A4E`, flag red `#F42A41` as a single sub-5% accent, off-white `#FAFAF8`, near-black `#0B0B0B` | tight Noto Serif Bengali display + Noto Sans Bengali 17px/1.75 | printed-document grid, roundel/seal, ruled tables, generous margins | Correct, but cold on its own |

### 7.2 Chosen direction — A + C hybrid (Surma Protocol)

C's document ethos and institutional trust fused with A's regional warmth. The site has to read as
official to a deputy commissioner *and* as credible to an 18-year-old in Sunamganj on a 4-inch
phone.

| Taken from | Element |
|---|---|
| **C** | Green institutional ground · flag-red accent under 5% of surface · Noto Serif Bengali display headings · the roundel/seal · ruler-straight numbering · ruled data tables · generous margins |
| **A** | Warm cream paper instead of white · deep tea-green `green-900` for the footer and dark bands · the Surma contour band · calm, unhurried vertical rhythm |

**Dropped from both:** C's `#FAFAF8` white-out (A's cream wins) and `#0B0B0B` near-black (A's warmer
`#0B1410` wins); A's `#8FBF4D` lime accent, which reads "eco brand" — flag-red takes that role.

### 7.5 Signature elements

Because there are **no photographs**, the visual language carries more weight than usual. These are
the deliberate moves that keep the site from looking unfinished:

1. **The document rule** — a 1px hairline with a 6×6px square tick, used as section dividers, list
   markers and table edges. Echoes government form typography.
2. **The roundel** — a circular seal (`DYD · AI · সিলেট · ব্যাচ ১`) in the header, footer and as the
   loading state. One recognisable institutional symbol.
3. **Surma contour band** — a low-contrast SVG contour pattern on the hero and footer only.
4. **Name-first participant cards** — with no portrait, the participant's **name is set large in
   Noto Serif Bengali** with district/upazila as a ruled meta line beneath. The card reads as a
   register entry, which is exactly what it is.
5. **Ruled data tables** — district counts, outcome breakdowns and the cohort summary are real
   ruled tables with aligned tabular numerals, not floating stat cards.
6. **Bangla numerals in the large statistics** — ৩০০ ঘণ্টা, ৪১ উপজেলা, ১ম ব্যাচ — set at display
   size.

### 7.6 Anti-slop rules

**Banned:** purple/violet/indigo gradients · emoji as iconography · everything centred · three
identical rounded pastel cards in a row · glassmorphism · drop-shadow on every element · generic
hero with a floating fake dashboard · stock photography of any kind · autoplaying carousels ·
`border-radius: 24px` everywhere · "AI-powered" as a headline · the words *seamless*,
*revolutionise*, *unlock*, *elevate*.

**Required:** real content (real names once consented, real upazila names, real dates) · one loud
colour used once · visible rules and alignment instead of shadows · left-aligned prose · tabular
numerals · self-hosted fonts · mobile-first at 360px · **no AI-generated imagery anywhere**.

#### 7.6.1 Enforced by the theme, not by discipline

| Banned pattern | How Tailwind v4 makes it impossible |
|---|---|
| Purple/violet/indigo/blue gradients | `--color-*: initial` wipes the palette; those classes do not compile |
| `border-radius: 24px` everywhere | `--radius-*: initial` + only `xs/sm/md/lg/pill` — no `rounded-3xl` |
| Drop-shadow on everything | `--shadow-*: initial` + only `shadow-1/2/3`, all quiet |
| Glassmorphism | No `backdrop-blur` token exposed |
| Emoji iconography | Icons come from one inlined SVG sprite; no emoji font stack |

`tools/check-css.py` fails the build if the compiled CSS contains a multi-hue gradient, a radius
above 12px outside `--radius-pill`, a shadow with a blur over 32px, or `backdrop-filter`.

## 8. Build & Tooling

### 8.1 Tailwind

| Option | Verdict |
|---|---|
| `npx @tailwindcss/cli` on the server during deploy | ❌ needs Node + npm install on cPanel |
| Tailwind Play CDN | ❌ ships the whole engine to the user |
| **Standalone CLI locally/CI → commit `app.css`** | ✅ **Chosen.** The server needs no Node |

```
assets/tailwind/source.css   ← the only hand-written CSS (@theme + @utility)
app/static/css/app.css       ← COMPILED, MINIFIED, COMMITTED
package.json                 ← dev-only: tailwindcss v4
tools/tailwindcss.exe        ← standalone binary, for machines without Node
```

```json
"scripts": {
  "css:build": "tailwindcss -i assets/tailwind/source.css -o app/static/css/app.css --minify",
  "css:watch": "tailwindcss -i assets/tailwind/source.css -o app/static/css/app.css --watch",
  "css:check": "python tools/check-css.py",
  "design:build": "tailwindcss -i design-src/preview.css -o design-src/preview.out.css --minify",
  "design:watch": "tailwindcss -i design-src/preview.css -o design-src/preview.out.css --watch"
}
```

**Rules**
1. All CSS lives in `source.css`. No `<style>` blocks, no `@apply` in templates, no arbitrary values
   (`bg-[#123456]`).
2. `app.css` is committed. **CI runs `css:build` then `git diff --exit-code`** — if a template
   changed without a rebuild, the build fails and names the command.
3. `asset('css/app.css')` appends `?v=<sha256[:8]>` so a rebuild busts the 1-year cache.
4. CI fails if `app.css` exceeds **45 KB gzipped**.
5. Print styles for the participant register live in the same `source.css`.
6. The admin skin is a `.admin-scope` theme override — one stylesheet, two densities.

### 9.2 App factory

- `create_app(config_name)` loads `.env`, configures logging, registers **6 blueprints**, installs
  Bangla error pages (404 / 403 / 419 / 429 / 500), and adds `before_request` hooks for locale,
  maintenance mode and admin activity.
- Security headers in `after_request`: CSP, `X-Content-Type-Options`, `X-Frame-Options: DENY`,
  `Referrer-Policy`, `Permissions-Policy`, HSTS in production.
- Jinja filters: `bn_num`, `bn_date`, `bn_currency`, `mask_none`, `section_render`.
- The admin blueprint mounts at `ADMIN_URL_PREFIX` (default `ops-sylhet`) — `/admin` returns 404.

### 9.3 Section rendering and validation

Each section type is one Python module in `app/sections/` plus one template:

```python
class HeroSection(SectionBase):
    type = "hero"
    schema = {
        "heading_bn":    {"type": "str",  "required": True,  "max": 160},
        "subheading_bn": {"type": "str",  "required": False, "max": 320},
        "media_id":      {"type": "ref",  "model": "MediaItem", "required": False},
        "primary_cta":   {"type": "cta",  "required": False},
        "secondary_cta": {"type": "cta",  "required": False},
    }

    def context(self, payload, request):        # what the template needs
        return {"heading": payload["heading_bn"], "media": self.resolve_media(payload)}
```

**Why modules rather than a JSON blob rendered by a generic template:** validation, defaults,
media resolution and a per-type admin form all fall out of the same declaration. Adding a section
type is one file plus one template, and it cannot silently render garbage from a malformed payload.

Rules:
1. An unknown `type` in the database raises and is reported in the admin, rather than being skipped.
2. A section whose payload fails validation is **not rendered** and is flagged to the admin.
3. `rich_text` bodies pass through `bleach` with a strict allowlist on save **and** on render.
4. `sections` are rendered in `sort_order`; `is_visible = false` sections are skipped entirely, not
   hidden with CSS.

### 9.4 Database strategy

| Env | Engine |
|---|---|
| Local dev | SQLite (`instance/ai_sylhet.db`) |
| Production | **MySQL 8 / MariaDB** — `utf8mb4` / `utf8mb4_unicode_ci`, **mandatory** for Bangla |

`flask check-config` hard-fails on a non-`utf8mb4` database: a `latin1` schema mangles every Bangla
string silently. SQLAlchemy only — no raw SQL outside reviewed counting queries, which use `LIKE`
on a normalised `search_blob` column so they work on both engines.

### 9.5 Background work

No Celery or Redis. Everything is either fast-and-synchronous or handled by a nightly cron:

| Job | Mechanism |
|---|---|
| Image resize on upload | Synchronous (Pillow, ~200ms) |
| CSV import of participants | Synchronous up to 2,000 rows; above that, chunked via cron |
| Statistics cache | 300 s file cache; invalidated on any participant write |
| Nightly backup | `cron_backup.sh` |
| Retention sweep (unpublished records, expired exports, stale tokens) | `cron_retention.sh`, weekly |

### 11.3 Participant management

**List:** filters for district, upazila, outcome, consent state, published state, batch; free-text
search over `search_blob`; sortable columns; 50 per page; column chooser; CSV/XLSX export of the
current filtered set (watermarked with requester and timestamp).

**Bulk actions:** publish · unpublish · set outcome type · assign district · export.

> Bulk **publish** silently skips any record without consent and reports how many were skipped — it
> never publishes a name because someone selected "all".

**Detail:** fields in §5.1 minus the prohibited set, plus the consent panel and a "preview public
profile" link. Any attempt to tick `is_published` without consent shows a blocking Bangla message
naming the missing field.

### 11.4 CSV import

Needed because Batch 1 records will arrive as a spreadsheet.

1. **Upload** → detect encoding (UTF-8 / UTF-8-BOM) and delimiter.
2. **Map columns** → the admin maps each CSV column to a participant field; saved as a reusable
   preset.
3. **Dry run** → row-by-row report: valid / missing required / unknown district or upazila /
   consent absent / duplicate name. Nothing is written.
4. **Commit** → transactional; writes only valid rows; produces a downloadable error report for the
   rest.
5. **Audit** → an `imports` row with counts and the file hash.

Inevitable realities this must handle: Bangla names in a spreadsheet saved from Excel on Windows;
district names with and without the district suffix (সিলেট vs সিলেট জেলা); duplicate names in the same
upazila; consent recorded as `ha`/`হ্যাঁ`/`yes`/`1`.

## 12. Authentication & Security

### 12.1 The admin account

There is exactly one kind of user. No roles, no permissions matrix, no student accounts.

| Control | Implementation |
|---|---|
| Login | Email + password (bcrypt, cost 12) |
| TOTP 2FA | **Required** — this single account controls all public content |
| Recovery codes | 10 single-use codes, shown once at enrolment |
| Rate limit | 3 attempts / 10 min, then a 30-minute lock; every attempt in `login_attempts` |
| Session | 30 min idle, 8 h absolute, `Secure` + `HttpOnly` + `SameSite=Lax`, id rotated at login |
| Non-guessable path | `ADMIN_URL_PREFIX` (default `ops-sylhet`); `/admin` returns 404 |
| IP allowlist | Optional `ADMIN_IP_ALLOWLIST` (CIDR); recommended once the site is live |
| Audit | Every write with a before/after diff; every login success and failure |

**Why 2FA is mandatory here:** compromising one password would let an attacker publish or unpublish
any participant, including altering who appears on a government page. There is no second account to
notice the change and no role separation to contain it.

### 12.2 Public surface protection

| Threat | Control |
|---|---|
| CSRF | `CSRFProtect` globally; every POST carries a token |
| XSS | Jinja autoescape; **no `\|safe` on user content**; `rich_text` sanitised by `bleach` on save and render |
| SQL injection | SQLAlchemy parameterised queries only |
| Upload RCE | Files stored **outside the webroot**; magic-byte sniffing; Pillow re-encode; random names; `/media/` serves `Content-Disposition: attachment` with `nosniff`; the upload directory has no execute permission |
| Path traversal | `secure_filename` + explicit allowlist + `realpath` containment check |
| Contact-form spam | Honeypot + minimum-time-on-form + Cloudflare Turnstile + 3 submissions per IP per hour |
| Participant enumeration | Rate-limit `/batch-1` filters; no incremental IDs anywhere — only slugs |
| PII leakage | Schema cannot store prohibited fields (§5.2); no PII in logs; `robots.txt` disallows only `/admin/` |
| Clickjacking | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` |
| Transport | HSTS 1 year; HTTPS forced in `.htaccess` |

### 12.3 Security headers

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline';
  script-src 'self' https://challenges.cloudflare.com; frame-src https://challenges.cloudflare.com;
  font-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'self';
  frame-ancestors 'none'; object-src 'none'; upgrade-insecure-requests
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()
```

`'unsafe-inline'` is required for styles by the section editor's live preview; scripts have no inline
exception.

### 12.4 Privacy commitments

- The privacy policy page is **required** and must state: what participant data is published, that
  photographs are not published, how consent is recorded, how to withdraw consent, and the contact
  for a withdrawal request.
- A withdrawal request must be actionable **within 24 hours** by the admin. The RUNBOOK documents
  the exact steps (`§18.4`).
- Retention: unpublished participant records are kept (the department needs them); contact messages
  are purged after 12 months; audit logs after 36 months.
- No third-party analytics by default. If analytics are wanted, self-hosted Plausible/Umami — never
  Google Analytics, because referral and IP data for a page of named individuals is a liability.

## 13. Media & Uploads

### 13.1 Pipeline

```
upload → size check (≤ 6 MB) → magic-byte sniff (not extension) → Pillow open
       → EXIF strip → convert to sRGB → resize to max 2000px long edge
       → re-encode (JPEG q82 / WebP q80) → generate thumbs (640, 320)
       → random filename → write to UPLOAD_ROOT (outside webroot)
       → MediaItem row (path, mime, width, height, size, alt_bn)
```

Serving: `/media/<path>` through a **signed, expiring URL**; never executed; `nosniff`; no directory
listing; `Cache-Control: public, max-age=31536000, immutable` because filenames are content-random.

### 13.2 Constraints

| Rule | Reason |
|---|---|
| JPEG, PNG, WebP only | No SVG uploads — SVG can carry script |
| ≤ 6 MB, ≥ 640px wide | Below 640px is useless on a retina display |
| `alt_bn` **required** on save | Accessibility is not optional on a government site |
| `used_count` maintained | An admin cannot delete an image still in use — blocks are prevented, not broken |
| Tags | Free-form, for library filtering |
| Video | **Links only** (YouTube/Facebook), never hosted files. `media_feature` and `gallery_strip` accept a `video_link` kind. |

### 13.3 No participant photographs

Reinforced here because it is the rule most likely to be tested by a well-meaning future request:
`participants` has no media reference and the CMS participant form has no image field. Portrait
support would require a consent programme (§5.2), not a field addition.

Training photographs are permitted **in the gallery only**, and must not be captioned with a
participant's full name.

## 14. Bangla Language, Fonts & Numbers

### 14.1 Locale

- Bangla is primary. `BABEL_DEFAULT_LOCALE = 'bn'`. English is not offered in v1.
- Locale is a cookie, not a URL prefix — links stay short and SMS-safe.
- Numbers, dates and figures are formatted at render, never stored formatted.
- Latin numerals in data contexts (counts in tables, codes); Bangla numerals in prose and display
  statistics.

### 14.2 Fonts (self-hosted, no CDN)

| Font | Use | Weight |
|---|---|---|
| Noto Serif Bengali | Display headings, participant names | 600, 700 |
| Noto Sans Bengali | Body, UI, forms | 400, 500, 600 |
| IBM Plex Sans | Numerals, tabular data | 400, 500 |
| Kalpurush | Fallback, print | 400 |
| Nikosh | Institutional/print headings | 400 |

`font-display: swap`, `unicode-range` for the Bengali block so Latin-only pages skip Bengali fonts.
Critical-path font budget **≤ 220 KB**, preloading only the two above-the-fold faces.

### 14.3 Bangla typography rules

Enforced globally in `source.css`, not per-component:

```css
[lang="bn"]                    { letter-spacing: normal; text-transform: none; }
[lang="bn"] h1, [lang="bn"] h2 { font-family: var(--font-display); text-wrap: balance; }
.prose-bn                      { max-width: var(--container-prose); line-height: 1.75;
                                 overflow-wrap: anywhere; }
.prose-bn a:not(.btn)          { text-decoration: none; border-bottom: 1px solid currentColor; }
.num, .font-num                { font-variant-numeric: tabular-nums; letter-spacing: 0; }
```

- No `letter-spacing` on Bangla — it breaks conjunct spacing.
- No `text-transform` on Bangla.
- No underline on Bangla prose links — it collides with matras. Use a bottom border and colour.
- Line-height ≥ 1.7.
- Never `hyphens: auto` — there is no Bangla hyphenation dictionary.
- Dates: `২৩ সেপ্টেম্বর ২০২৬` in prose, `২৩/০৯/২০২৬` in tables. Times with Bangla prefixes —
  সকাল / দুপুর / বিকাল.

Because these are attribute-scoped global rules, `<h2 lang="bn" class="tracking-wide uppercase">`
still renders correctly regardless of what a developer types.

### 14.4 Input handling

- All text normalised to **NFC** on save.
- Zero-width joiner/non-joiner preserved in display fields, stripped from `search_blob`.
- Name search matches both Bangla and Latin, ignoring zero-width characters.
- Bangla and Latin digits both accepted in numeric fields, converted on save.

### 15.1 Performance budget

| Metric | Target |

| CLS | < 0.05 |

is also a privacy bug, so it is covered by an explicit test (§19.2).

### 17.3 `deploy.sh`

Same shape as the owner's proven Favonia script: ssh-agent for a passphrase key, rsync → tar
fallback, `--setup` / `--install-deps` / `--with-db` / `--setup-cron`, plus:

```
Flags
  --migrate            flask db upgrade
  --seed               flask seed (idempotent)
  --build-css          npm run css:build locally first
  --check-css          npm run css:check, abort on failure
  --allow-stale-css    override the stale-CSS abort
  --backup             take a DB + uploads backup first
  --full               --build-css --check-css --backup --install-deps --migrate --restart --verify

Pre-flight (aborts)
  1. SSH key present; ssh-agent loaded (passphrase asked once)
  2. SSH auth succeeds
  3. remote app root exists; disk free > 500 MB
  4. local git tree clean (warn + 5s window)
  5. hard guard: the remote path is NOT the national app root
  6. CSS freshness: app.css newer than source.css AND every template — abort if stale
  7. optional --build-css / --check-css

Sync excludes: .env* · instance/*.db · Keys/ · PEM/ · var/ · uploads/ · .git/
               .htaccess · assets/ · design-src/ · node_modules · package*.json
               tests/ · docs/ · *.css.map
  (app/static/css/app.css IS synced — it is the shipped artifact)

Deploy steps
  1. release archive created (for rollback.sh)
  2. mkdir runtime dirs; chmod upload root 750
  3. .env must exist — never auto-created
  4. verify DB charset is utf8mb4 — abort otherwise
  5. verify app.css arrived and is > 20 KB
  6. --install-deps / --migrate / --seed as flagged
  7. flask check-config
  8. maintenance mode on → touch tmp/restart.txt → wait for /health
  9. smoke tests (fail the deploy on any failure):
       GET /                    → 200, contains "সিলেট"
       GET /batch-1             → 200, contains "প্রশিক্ষণার্থী"
       GET /course              → 200, contains "কোর্স"
       GET /privacy             → 200 and mentions consent
       GET /admin               → 404
       GET /ops-sylhet/login    → 200
       GET /robots.txt          → 200, Disallow: /ops-sylhet/

 10. maintenance mode off; print revision, css hash, health, elapsed

Exit codes: 0 ok · 1 pre-flight · 2 auth · 3 sync · 4 remote · 5 smoke · 6 config · 7 stale CSS
```

Lists the last 10 release archives, restores one over the app root (excluding `.env` and
`.htaccess`), optionally `flask db downgrade` with `--db` and a loud data-loss warning, restarts
Passenger, re-runs the same smoke tests.

**`ci.yml`** on every push:
`npm ci` → `npm run css:build` → `git diff --exit-code app/static/css/app.css` (drift gate) →

### 18.2 The two operational workflows that matter

**Adding Batch 1 participants (spreadsheet → live)**

```
1. Prepare the CSV with the §5.1 columns only. Do not include phone, email or ID numbers.
2. Admin → Participants → Import
3. Upload → map columns (save the preset) → DRY RUN
4. Read the dry-run report. Fix the source for: missing required fields, unknown
   district/upazila, consent absent, duplicate names.
5. Commit. Only valid rows are written.
6. Open the consent dashboard. Any record without a consent_date shows here.
7. Bulk publish — records without consent are skipped and the count is reported.
8. Spot-check 5 profiles on the public site, including on a phone.
```

**Withdrawing consent (must complete within 24 hours)**

```
1. Receive the request (phone, email or in person). Record who asked and when.
2. Admin → Participants → find the record → Consent panel
3. Set consent_withdrawn_at = now. Save.
   → is_published clears automatically in the same transaction
   → the participant and statistics caches are invalidated
4. Verify: the public profile returns 404; the participant no longer appears in
   /batch-1, in district pages, or in any statistic.
5. Log it: consent_events records the withdrawal with the source and note.
6. Reply to the requester confirming removal.
The record is NOT deleted — the department needs the audit trail.
```

## 19. Testing & QA

### 19.1 Pyramid

| Level | Tool | Scope | Gate |
|---|---|---|---|
| Unit | pytest | validators, section schemas, slug generation, statistics suppression, Bangla formatting | 70% on `app/services` |
| Integration | pytest + test client | every route: status, auth, filters, pagination | every route in §6.2 |
| Data | pytest | migrations reversible; the §10.4 publish CHECK constraint | must pass |
| E2E | Playwright | the 6 journeys in §19.2 | before release |
| Visual | Playwright screenshots | 5 public pages at 360/768/1440 | baseline tracked |
| A11y | axe-core + manual | public + admin forms | zero serious/critical |
| Load | locust | 300 concurrent reader sessions | no 5xx; p95 < 1.5 s |
| Security | bandit, pip-audit, manual | §12 controls | zero high |

### 19.2 Journeys that must pass

1. **A visitor finds a participant** — filter by district, search by name in Bangla, open a profile.
2. **A non-consented participant is invisible** — direct slug URL → 404; absent from lists, counts
   and statistics.
3. **Consent withdrawal propagates immediately** — withdraw, then reload the profile, the cohort
   list and the district page → gone from all three.
4. **The publish guard holds** — attempting `is_published = true` without consent fails at the form,
   at the model, and at the database.
5. **The small-cell rule holds** — a statistic derived from fewer than 5 records renders `—`.
6. **An admin publishes a page** — add sections, reorder, toggle visibility, preview, publish, and
   see it live.
7. **CSV import** — a dry run with mixed valid/invalid rows writes nothing; the commit writes only
   valid rows and produces an error report.
8. **Admin auth** — wrong password 3× locks the account; TOTP is required; a recovery code works once.

### 19.3 Fixtures

- **Bangla edge cases** — conjunct names (`বিষ্ণুপ্রসাদ`), zero-width joiners, NFC/NFD variants,
  Bangla digits in numeric fields, single-word names, 60-character names, mixed Bangla/Latin.
- **Consent matrix** — granted / absent / withdrawn / missing date / date in the future.
- **Import cases** — UTF-8 and UTF-8-BOM CSVs, semicolon delimiter, header typos, district names
  with and without "জেলা", consent recorded as `ha`/`হ্যাঁ`/`yes`/`1`, 500 rows with 40 errors.
- **Upload cases** — a 12 MB JPEG, a `.jpg` that is really a PDF, a `.png` with EXIF GPS, a CMYK
  JPEG, a 1×1 px image, a null byte in the filename.

### 19.4 Definition of Done

```
□ Route + CSRF + validation in place
□ Section type (if new): schema, template, admin form, unit test
□ Bangla copy reviewed by a Bangla speaker
□ Empty / loading / error / 403 / 404 states implemented
□ Keyboard-navigable; visible focus; labels associated; errors announced
□ 360 / 768 / 1440 verified; no horizontal scroll
□ Tests written; the relevant §19.2 journey passes if touched
□ Audit row written on every mutation
□ Lists paginated; queries indexed
□ Consent rules respected if the change touches participants or statistics
□ No `<style>`, no @apply, no arbitrary Tailwind values; css:build run and app.css committed
□ No banned pattern from §7.6
□ ADMIN_GUIDE / RUNBOOK updated if the operator's workflow changed
```

## 21. Risks

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| **R1** | **A participant is published without valid consent** | Medium | **Critical** | Three-layer guard: form, model, and a database `CHECK` constraint (§10.4). Consent dashboard surfaces missing dates. Non-consented records are excluded from every public query, count and search. |
| **R2** | **Consent is withdrawn but the person stays visible via a cache** | Medium | **Critical** | Cache invalidation happens in the same transaction as the withdrawal; an explicit E2E test (§19.2 journey 3) fails the build otherwise. |
| **R3** | **Prohibited data reaches the schema** (someone adds a phone or photo column) | Low | **High** | The columns do not exist (§10.4). Adding one is a deliberate migration, not a field addition. §5.2 is referenced from the model docstring. |
| **R4** | Participant names published before the department confirms consent records exist | **High** | **High** | Import defaults to unpublished; publish is a separate, explicit bulk action that skips non-consented rows and reports the count. |
| **R5** | Bangla text mangled by a non-`utf8mb4` database | Medium | **High** | `flask check-config` hard-fails; go-live checklist verifies it. |
| **R6** | Stale compiled CSS ships after a template change | Medium | Medium | CI drift gate, deploy pre-flight abort (exit 7), `flask check-config` warning. |
| **R7** | Section payloads drift from the schema and render garbage | Medium | Medium | Per-type schema validation at write and read; an unknown type raises and is reported rather than skipped. |
| **R8** | The single admin account is compromised | Low | **High** | Mandatory TOTP, recovery codes, 3-attempt lockout, 30-min idle timeout, optional IP allowlist, non-guessable admin path, full audit trail. |
| **R9** | Small-cell statistics identify individuals | Medium | Medium | Cells derived from <5 records render `—`; enforced in `stats_service` and tested. |
| **R10** | Batch 1 data does not exist in a usable form | Medium | Medium | CSV import with a dry run and Bangla-tolerant parsing (§11.4). |
| **R11** | Wrong institution or partner name published | Medium | Medium | §22 Q2/Q3 must be confirmed before the Course and About pages go live. |
| **R12** | Contact-form spam | High | Low | Honeypot, minimum time on form, Turnstile, 3 per IP per hour. |
| **R13** | The admin does not adopt the CMS | Medium | Medium | Bangla guide with screenshots, keyboard-friendly reordering, live preview, and a 60-minute recorded training session. |
| **R14** | Scope creep back toward the operational system | Medium | **High** | §2.2 lists what is not being built, with reasons. Anything new is a deliberate decision, not an addition. |
| **R15** | Media library grows unbounded and fills the disk | Low | Medium | `used_count` blocks deleting in-use images; monthly tidy task; disk check in the runbook. |
